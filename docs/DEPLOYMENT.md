# Deployment Guide

## 1. Local Docker Compose
```bash
cp .env.example .env
docker compose config
docker compose up --build -d
python scripts/wait_for_stack.py --url http://localhost:8080 --timeout 300
python tests/smoke/smoke.py
```
Before startup, set `HF_TOKEN` only in the local `.env` using `scripts/set-hf-token.ps1` (Windows) or `scripts/set-hf-token.sh` (Unix). The AI-triage and assistant containers contain no Llama weights or PyTorch runtime; both call Hugging Face Inference Providers over HTTPS. The default model is `meta-llama/Llama-3.1-8B-Instruct` and therefore requires model access, an inference-enabled token, available provider quota and outbound HTTPS.

## 2. Terraform AWS baseline
Prerequisites: AWS CLI identity, Terraform, accepted AWS cost, Docker/Jenkins host and an account/region in which the required services are allowed.
```bash
cd infrastructure/terraform
terraform init
terraform fmt
terraform validate
terraform plan -out campuspulse.tfplan
terraform apply campuspulse.tfplan
```
The default baseline provisions VPC/subnets/security groups, seven ECR repositories, private RDS PostgreSQL, Secrets Manager application values, IAM roles, blue/green Elastic Beanstalk environments, S3 deployment artefacts, CloudWatch/SNS alarms and optional CodeCommit/CodeBuild.

RDS is not publicly accessible. Application credentials are generated by Terraform unless an approved database password is injected through `TF_VAR_db_password`. Do not commit tfvars containing secrets.

## 3. Database bootstrap
RDS initially creates only the `postgres` database. The AWS Compose package contains a one-shot `db-bootstrap` using the auth image and `POSTGRES_ADMIN_URL`. It idempotently creates `campuspulse_auth`, `campuspulse_feedback`, `campuspulse_notifications` and `campuspulse_assistant`; normal services then run their own Alembic migrations.

## 4. Secrets
Terraform stores JWT/internal tokens, `HF_TOKEN`, and RDS URLs in AWS Secrets Manager. Elastic Beanstalk environment-secret settings expose only the specific JSON key required by the containers. The runtime Compose artefact contains variable names, not secret values. After secret rotation, follow AWS refresh guidance so existing instances receive the new value.

## 5. Build and push
Jenkins builds all seven lightweight application images; the assistant image contains only the API client, retrieval/guardrail code and application dependencies—no Llama weights. `infrastructure/aws/push-ecr.sh <git-sha>` authenticates and pushes immutable tags. Use the Git SHA, not only `latest`.

## 6. Elastic Beanstalk package
`infrastructure/aws/package-eb.sh <git-sha>` renders only account/region/image coordinates. Database/JWT values remain environment variables supplied by Beanstalk/Secrets Manager. Upload the ZIP as a new application version, then deploy it to the inactive environment.

## 7. Candidate verification and promotion
Run health/readiness/functional smoke tests against the inactive environment. AI and assistant readiness must confirm hosted-Llama configuration is present; optional explicit hosted-Llama smoke tests verify real triage and chat requests when a masked Jenkins `campuspulse-hf-token` credential is enabled. Promote by swapping environment CNAMEs only when candidate verification passes. Retain the previous environment for rollback.

## 8. AWS-native verification path
Push/mirror the Git commit to the Terraform-created CodeCommit repository. The CodeBuild project uses `buildspec.yml` to independently run lint/tests/evaluations/frontend build/Compose validation. This is supplementary to Jenkins, not an untracked manual build.

## 9. Production verification
Capture the live URL, ECR tag, RDS private status, EB enhanced health, CloudWatch logs/alarms and exact Jenkins commit. Run `python tests/smoke/smoke.py --base-url <production-url>` and record the result. Do not state AWS deployment is complete until these actions were actually executed.

## Cost/scalability note
The demonstration defaults to a single RDS instance and a `t3.medium` Beanstalk instance because hosted Llama removes local model RAM pressure. This is still only an academic baseline, not a production capacity recommendation. Production sizing requires load/latency/memory measurements, high-availability requirements and cost analysis.
